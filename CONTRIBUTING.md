# Contributing

Whether a plugin works depends on the compositor, the distribution and, for some plugins, the hardware.
I can only test a small part of that myself.
Testers with other setups are more than welcome: another compositor or distribution, another GPU vendor, another TV brand or a vertical bar.
Please report anything that does not work on your machine, and try the fix branches that I create for hardware-specific issues.

## Before you start

- Bigger changes: open an issue before you start a new plugin, a new feature, a new dependency or a refactoring, so we can agree on the approach first. Small fixes and translations can go straight to a pull request.
- AI: using AI tools to write code is fine, but you are responsible for the result. You have to understand every change, test it and be able to explain and discuss it. Mention in the PR if a meaningful part was generated.
- AI-written text: issues, PR descriptions and comments generated by AI are strictly forbidden and will be closed without discussion. If writing it yourself is not worth your time, reading it is not worth mine.
- Agents: [AGENTS.md](AGENTS.md) is the guide for AI agents. Make sure that any agent you use follows it and that you understand what it does. You remain solely responsible for the result.

## Setup

Development requires a running Dux Shell, `jq` and the Python package `jsonschema`.

```bash
./dev setup            # links ../dux-shell if it exists, otherwise clones the required parts
./dev link MyPlugin    # makes the plugin visible to the running shell
./dev reload MyPlugin  # after each change
./dev check            # validates the manifests and strings, the same check as CI
```

If the plugin is already installed from the registry, remove it in Settings > Plugins first, otherwise `./dev link` stops.
Load errors are shown by `./dev reload` and in `journalctl --user -u dms -f`.

### Cast

Cast requires [cast-helper](https://github.com/Conava/cast-helper), checked out next to this repository as `../cast-helper`.
`./dev link Cast` and `./dev reload Cast` build it with detailed logging, and the plugin uses that build instead of the installed helper.
The log is written to `~/.cache/dms/cast/serve.log`.
To test the setup screens for missing packages, run `FAKE_MISSING=a,b ./dev reload Cast`, which builds a helper that reports those packages as missing.

## Translations

Each plugin keeps its translations in `translations/<locale>.json` and uses the locale names of the shell (e.g. `de`, `es`, `pt`, `zh_CN`).
To start a new language or update an existing one, run:

```bash
./dev strings MyPlugin de
```

This writes every string of the plugin into `MyPlugin/translations/de.json`.
Fill in the empty values and open a PR.
Empty values are shown in English.
Run the command again later to add new strings.
Existing translations are kept.

## Making a change

- Scope: one plugin per PR.
- Version: bump `version` in `plugin.json` for every change that users notice.
- Checks: `./dev check` has to pass, otherwise CI fails.
- Testing: test the change in the running shell, on a horizontal and a vertical bar, in light and dark mode, and with the plugin disabled and enabled again. Mention the compositor and distribution in the PR, and for Cast also the GPU and the cast device.
- Screenshots: required for every visual change.
- Commits: `<plugin folder in lowercase>: short lowercase summary`, e.g. `cast: hide devices that cannot mirror`. Changes to the repository itself use `repo:`.
- Helper changes: if a Cast change also requires a change in cast-helper, open that PR in cast-helper and link both PRs.
